The Gemini CLI connector wires DefenseClaw into
[Google's Gemini CLI hooks](https://geminicli.com/docs/hooks/) and points the
agent's native OTLP exporter at the gateway so traces, metrics, and logs land
in one place.

<Callout type="warning" title="Continuing paid and enterprise product only">
Google ended Gemini CLI service for consumer/free/Google AI Pro/Ultra users on
June 18, 2026 and directs that audience to Antigravity CLI. This connector is
only for the officially continuing Gemini Code Assist Standard/Enterprise,
Google Cloud, and paid Gemini API or Gemini Enterprise Agent Platform API-key
paths. It does not restore consumer Gemini CLI access. See
[Google's transition announcement](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/)
and the [Antigravity migration guide](https://antigravity.google/docs/cli/gcli-migration).
</Callout>

<Callout type="warning" title="Native Windows is implemented but not certified">
Gemini CLI itself documents native Windows 11 24H2+, Node.js 20+, and
PowerShell. DefenseClaw keeps this connector `not_certified` on Windows until a
credentialed official-client run proves hooks, enforcement, OTLP, Doctor, and
teardown end to end. Native Setup labels the staged Gemini lifecycle choice as
enterprise/Cloud/paid-key and certification-pending; that selection is not a
support or certification claim, and runtime activation remains platform-gated.
Do not use WSL, Git Bash, Docker, or another compatibility layer as a workaround.
</Callout>

## Setup

```bash
defenseclaw setup geminicli
```

`setup geminicli` is shorthand for `setup guardrail --connector geminicli`: it
adds or reconfigures the continuing paid/enterprise Gemini CLI product, wires
all 11 documented lifecycle events against `~/.gemini/settings.json`, and
points Gemini's native OTLP exporter at the gateway. **There is no
proxy-enforcement path** for Gemini CLI — blocking happens hook-side on
`BeforeAgent`, `BeforeModel`, `BeforeTool`, `AfterTool`, and `AfterAgent`.
Gemini CLI has no native ask surface, so confirm verdicts use an immediate
alert/context fallback with `raw_action` preserved for audit.

#### What `setup geminicli` actually does

The wrapper accepts exactly three flags. The underlying guardrail config falls back to the values DefenseClaw ships with — schema-defined in [`internal/config/config.go`](https://github.com/cisco-ai-defense/defenseclaw/blob/main/internal/config/config.go) and documented on the [Defaults page](/docs/defaults).

| Flag | Default | What it does |
| --- | --- | --- |
| `--yes / -y` | off | Skip the confirmation prompt (alias: `--non-interactive`, `--accept-defaults`). |
| `--restart / --no-restart` | `--restart` | Bounce `defenseclaw-gateway` after applying changes so the new hooks + OTLP env vars wire in. |
| `--with-local-stack / --no-local-stack` | `--no-local-stack` | Also bring up the bundled Prom/Loki/Tempo/Grafana stack via `setup local-observability up`. |

Redaction remains a v8 bucket/profile policy (`none` for fresh v8). Edit `observability.destinations[].routes[].selector.buckets` and `observability.redaction_profiles`; then follow [Redaction → Verify policy](/docs/reference/redaction#verify-policy).

The alias defaults Gemini CLI to observe mode and can join an existing hook-connector roster when you choose **Add**. To tune Gemini CLI after install, keep using [`defenseclaw setup guardrail --connector geminicli`](/docs/setup/guardrail) — see the variations below.

#### Common variations — pick the recipe that fits your phase

<Tabs items={['Standard', 'Local stack', 'Add scanning rigor', 'Hook-side enforcement']}>

<Tab value="Standard">

```bash
defenseclaw setup geminicli
```

Confirms once, wires the hooks against `~/.gemini/settings.json`, points OTLP at the gateway, and restarts the gateway. Findings flow to mandatory SQLite event history and the TUI; configured v8 destinations receive only the buckets/signals their routes select. No traffic is intercepted and no requests are blocked. Pass `--yes` to skip the confirmation in CI.

</Tab>

<Tab value="Local stack">

```bash
defenseclaw setup geminicli --yes --with-local-stack
```

Same as standard but also runs `setup local-observability up` so Prom/Loki/Tempo/Grafana come up locally — particularly useful for Gemini since native OTLP feeds traces and metrics directly into Tempo and Prometheus. See [Local observability](/docs/observability/local-observability).

</Tab>

<Tab value="Add scanning rigor">

```bash
export DEFENSECLAW_LLM_KEY='replace-with-your-key'

defenseclaw setup geminicli                               # base alias first
defenseclaw setup guardrail \
  --connector geminicli \
  --rule-pack strict \
  --scanner-mode both \
  --detection-strategy regex_judge \
  --judge-model anthropic/claude-sonnet-4-20250514 \
  --judge-api-key-env DEFENSECLAW_LLM_KEY \
  --restart
```

The alias selects Gemini CLI; the follow-up `setup guardrail --connector geminicli` swaps in the strict rule pack, runs both local + [Cisco AI Defense](https://www.cisco.com/site/us/en/products/security/ai-defense/index.html) scanners, and turns the LLM judge on as a second-pass adjudicator on regex-flagged events.

</Tab>

<Tab value="Hook-side enforcement">

Gemini CLI has no proxy enforcement, but its hooks themselves can block. After `setup geminicli`, edit `~/.defenseclaw/config.yaml` and set the per-connector hook mode:

```yaml
connector_hooks:
  geminicli:
    enabled: true
    mode: action          # observe (default) | action
    fail_mode: open       # open | closed
```

Then `defenseclaw setup guardrail --restart` to re-wire. With `mode: action`, Gemini's lifecycle hooks block when policy returns `block`. Because Gemini CLI has no native ask surface, `confirm` uses an alert/context fallback; operators can review the event in audit or the TUI, but cannot resume it there.

</Tab>

### Coexistence with Antigravity

Gemini CLI and Antigravity share the `%USERPROFILE%\.gemini` parent directory,
but they do not share DefenseClaw custody. The Gemini CLI connector owns only
its marked entries in `.gemini\settings.json`, its
`.defenseclaw\connector_backups\geminicli\config.json` restoration record, and
its `.otlp-geminicli.token`. Antigravity hook and MCP state beneath
`.gemini\config\`, Antigravity CLI state beneath `.gemini\antigravity-cli\`,
credentials, extensions, agents, skills, and unrelated Google files are
outside Gemini teardown authority.

Setup, repair, deferred uninstall, and reconciliation persist the exact
`.gemini` configuration directory only so the hidden DefenseClaw
`--config-home` maintenance command can resolve `settings.json`. DefenseClaw
does not define or export a Gemini client home variable. Teardown restores or
removes only DefenseClaw-owned Gemini CLI fields and then revokes the Gemini
OTLP path token; it never deletes the shared `.gemini` directory.

### Synchronous response and failure boundary

For awaited events, Gemini CLI writes one JSON object to hook stdin, waits for
the configured process, and parses JSON from stdout. `SessionEnd` is an
upstream best-effort event and is not awaited; `Notification` and
`PreCompress` are observation-only. DefenseClaw intentionally returns exit 0
with `{"decision":"allow"}` or `{"decision":"deny","reason":"..."}`; an
alert fallback may add Gemini's documented `systemMessage` field alongside
`decision:"allow"`. This is the documented JSON decision path and avoids
relying on a contradiction between Gemini's hook reference and the v0.53.0
legacy nonzero-result conversion.

The configured Gemini timeout is 30,000 ms. DefenseClaw fail-open/fail-closed
handling covers adapter failures after the native launcher starts, including
gateway authentication, transport, invalid responses, and oversized input. If
Gemini itself cannot spawn the launcher, or kills it at the host timeout before
it can reply, no adapter can manufacture stdout. Failures before adapter start,
host launch failures, host-enforced timeouts, and host-side collapse of
arbitrary nonzero process exits remain upstream/live-certification boundaries;
they are not covered by DefenseClaw's fail-closed claim. Doctor therefore
validates the exact launcher, every event, timeout, OTLP credential, and
contract evidence before reporting a healthy native registration.
