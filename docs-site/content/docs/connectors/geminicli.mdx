The Gemini CLI connector wires DefenseClaw into
[Google's Gemini CLI hooks](https://geminicli.com/docs/hooks/) and points the
agent's native OTLP exporter at the gateway so traces, metrics, and logs land
in one place.

<Callout type="warning" title="Native Windows preview">
Gemini CLI itself supports native Windows. DefenseClaw's native integration is
currently **preview**: Setup binds the official Gemini home, registers the native
system-PowerShell launcher for all 11 lifecycle events, and restores only
DefenseClaw-owned handlers during teardown. Synchronous events are awaited;
Gemini runs `PreCompress` asynchronously and delivers `SessionEnd` on a
best-effort basis. WSL, Git Bash, and a POSIX hook script are not used. Packaged
and authenticated official-client live evidence is still pending, so this is
not a Windows certification claim.
</Callout>

## Setup

```bash
defenseclaw setup geminicli
```

`setup geminicli` is shorthand for `setup guardrail --connector geminicli`: it
adds or reconfigures Gemini CLI, wires
all 11 documented lifecycle events in the bound user `.gemini/settings.json`, and
points Gemini's native OTLP exporter at the gateway. **There is no
proxy-enforcement path** for Gemini CLI — blocking happens hook-side on
`BeforeAgent`, `BeforeModel`, `BeforeTool`, `AfterTool`, `AfterModel`, and
`AfterAgent`.
Gemini CLI has no native ask surface, so confirm verdicts use an immediate
alert/context fallback with `raw_action` preserved for audit.

### Home, settings, and inventory scope

`GEMINI_CLI_HOME` is Gemini's official **home-root** override, not its config
directory. User settings therefore live at
`<GEMINI_CLI_HOME>/.gemini/settings.json`; without the override the default is
`~/.gemini/settings.json`. On native Windows, Setup accepts a non-empty ambient
`GEMINI_CLI_HOME` only when it is absolute, normalized, control-free, has no
surrounding whitespace, and has no unsafe reparse-point ancestry. A non-empty
value that fails those checks makes Setup fail closed; only an absent or exactly
empty value falls back to the signed-in Profile Known Folder, producing
`%USERPROFILE%\.gemini`. The unsupported `GEMINI_CONFIG_DIR` variable is
ignored.

The native install state retains both the accepted home root and its derived
`.gemini` config directory. Packaged launchers and the gateway discard ambient
Gemini home/config bindings, then rehydrate authenticated `GEMINI_CLI_HOME` and
the private `DEFENSECLAW_GEMINI_CONFIG_HOME` binding; repair and upgrade
preserve both values.

MCP inventory reads the trusted project's `<workspace>/.gemini/settings.json`
before the user settings file. Skills and agents use the selected workspace's
`.gemini/skills` and `.gemini/agents` roots. Extensions are discovered read-only
from the user-global `.gemini/extensions` below the bound home root (normally
`~/.gemini/extensions`); Gemini CLI has no workspace extension installation
root.

Gemini accepts JSONC-style comments in `settings.json`. DefenseClaw accepts
those comments when reading, but a managed hooks or telemetry write serializes
the document as formatted canonical JSON, so comments and the original
formatting are not preserved. Trailing commas remain invalid.

<Callout type="warning" title="Effective settings are launch-scoped">
Setup and verification check the authenticated user settings, the current or
explicitly pinned trusted workspace, applicable system settings/overrides, and
the effective process environment and `.env` inputs. An arbitrary future or
unpinned trusted workspace (or a different launch environment) can still
disable hooks or redirect telemetry. Until DefenseClaw enforces these settings
at every launch, action-mode blocking and native OTLP remain preview and
conditional on those effective settings. DefenseClaw does not install a managed
Gemini wrapper, so it cannot pin the recorded home and effective settings for a
later process launched from a different environment or workspace.
</Callout>

#### What `setup geminicli` actually does

The table highlights convenience options rather than the complete alias
surface. The alias also accepts `--mode`, `--rule-pack`, `--fail-mode`,
approval, block-message, add/replace, workspace, and rule-pack-directory
options. See the [quick-alias reference](/docs/setup/guardrail/aliases); use
[full guardrail setup](/docs/setup/guardrail) for scanner, detection-strategy,
and judge-provider configuration.

| Flag | Default | What it does |
| --- | --- | --- |
| `--yes / -y` | off | Skip the confirmation prompt. |
| `--restart / --no-restart` | `--restart` | Bounce `defenseclaw-gateway` after applying changes so the new hooks + OTLP env vars wire in. |
| `--with-local-stack / --no-local-stack` | `--no-local-stack` | Also run `setup local-observability up`; follow the command's printed gateway-restart step after it writes the export destination. |

Redaction remains a v8 bucket/profile policy (`none` for fresh v8). Edit `observability.destinations[].routes[].selector.buckets` and `observability.redaction_profiles`; then follow [Redaction → Verify policy](/docs/reference/redaction#verify-policy).

The alias defaults Gemini CLI to observe mode and can join an existing hook-connector roster when you choose **Add**. To tune Gemini CLI after install, keep using [`defenseclaw setup guardrail --connector geminicli`](/docs/setup/guardrail) — see the variations below.

#### Common variations — pick the recipe that fits your phase

<Tabs items={['Standard', 'Local stack', 'Add scanning rigor', 'Hook-side enforcement']}>

<Tab value="Standard">

```bash
defenseclaw setup geminicli
```

Confirms once, wires the hooks in the bound user `.gemini/settings.json`, points OTLP at the gateway, and restarts the gateway. Findings flow to mandatory SQLite event history and the TUI; configured v8 destinations receive only the buckets/signals their routes select. No traffic is intercepted and no requests are blocked. Pass `--yes` to skip the confirmation in CI.

</Tab>

<Tab value="Local stack">

```bash
defenseclaw setup geminicli --yes --with-local-stack
```

Same as standard but also runs `setup local-observability up` so Prom/Loki/Tempo/Grafana come up locally — particularly useful for Gemini since native OTLP feeds traces and metrics directly into Tempo and Prometheus. That command writes the export destination after the alias has already restarted the gateway, so run its printed `defenseclaw-gateway restart` step before expecting exports. See [Local observability](/docs/observability/local-observability).

</Tab>

<Tab value="Add scanning rigor">

```bash
export DEFENSECLAW_LLM_KEY='replace-with-your-key'

defenseclaw setup geminicli                               # base alias first
defenseclaw setup guardrail \
  --connector geminicli \
  --rule-pack strict \
  --scanner-mode local \
  --detection-strategy regex_judge \
  --judge-model anthropic/claude-sonnet-4-20250514 \
  --judge-api-key-env DEFENSECLAW_LLM_KEY \
  --judge-hook-connectors geminicli \
  --restart
```

The alias selects Gemini CLI; the follow-up `setup guardrail --connector geminicli` swaps in the strict rule pack, keeps scanning local, and turns the LLM judge on as a second-pass adjudicator on regex-flagged events. Configure the remote scanner separately through [full guardrail setup](/docs/setup/guardrail), which validates its endpoint and API-key environment variable.

</Tab>

<Tab value="Hook-side enforcement">

Gemini CLI has no proxy enforcement, but its hooks can enforce directly:

```bash
defenseclaw setup geminicli --mode action --fail-mode closed
```

With `mode=action`, the declared blocking hooks stop policy-denied work.
Because Gemini CLI has no native ask surface, `confirm` uses an alert/context
fallback; operators can review the event in audit or the TUI, but cannot
resume it there.

</Tab>

</Tabs>
